title: ACP Chat State And History Authority
type: ai-coding-rule
appliesTo:
  - acp-chat-experience
  - acp-file-activity
  - gateway-backend-communication
---

Main owns ACP process, SDK, routing lifecycle, and serialization of operations on the shared ACP connection; Renderer owns semantic reduction into an in-memory timeline. A newly created non-default Agent's `agent:<id>:main` conversation uses its sanitized first prompt as the initial sidebar title and remains eligible for transcript-summary title hydration after reload; synthetic transport names such as `ACP` are not user-facing conversation titles. The canonical `agent:main:main` session is bound to the default workspace for execution and sidebar grouping, even when stale ACP replay metadata reports another Agent's cwd. After Main confirms permanent Agent deletion, Renderer must atomically forget every session, label, activity record, draft, hydration marker, and attention record under the exact canonical `agent:<deletedId>:` prefix, retain that Agent ID as an in-memory catalog tombstone, and reject matching list rows and live or buffered events until an authoritative Agent snapshot contains that ID again. Agent-list responses that predate a confirmed Agent mutation must not publish or reconcile against these tombstones. It must then repair a deleted current selection without creating a placeholder for the deleted Agent. A failed Main deletion must leave Renderer chat state unchanged. Unsent composer text and its textarea caret or selection are Renderer-owned, memory-only UI state keyed by the exact conversation session key: switching conversations must show that conversation's own draft (or an empty composer), returning must restore both the draft and its last valid selection, a draft without a remembered selection must place the caret at the end, and sending must clear only the submitted conversation's draft. The local ACP child receives the authoritative `gatewayToken` from Electron store through `OPENCLAW_GATEWAY_TOKEN`; it must not rely on a separately resolved OpenClaw config credential or expose the token through CLI arguments or Renderer state. Notifications emitted during `session/load` are returned as one generation-scoped raw batch and reduced in one Renderer state commit. Renderer may temporarily buffer matching host events during the IPC result handoff, while each ordinary live prompt update continues through host events and is applied immediately without a Renderer batching timer. Within one live prompt, a strict extension of the same assistant snapshot emits only its unseen suffix, an identical or stale prefix emits nothing, and any non-prefix assistant update is emitted in full; a prior update length must never drop a shorter trailing fragment or slice a new segment. A pending prompt may retain a bounded Main routing context and Renderer timeline snapshot so navigation cannot drop its stream; those contexts must be keyed by session and generation, remain memory-only, and be released when the prompt settles. Reactivating that live snapshot must preserve its running turn timing and must not start historical timing supplementation against the prompt's partial transcript. Gateway restart recovery must use explicit source-run lineage from trusted OpenClaw recovery provenance; ACP may adopt a new run only when `resumedFromRunId` matches its pending prompt, and Renderer must not reload a session based on Gateway runtime identity. An acknowledged prompt may remain pending for the Main-computed heartbeat detection and managed Gateway startup budget, currently about ten minutes, while an unacknowledged send retains the 5-second deadline. A renderer-only reload without the live memory snapshot must wait for normal ACP replay rather than converting repeated active-prompt responses into a load failure. Permission requests are interactive only for an active prompt. Stale session generations are ignored, and ClawX does not persist a second ACP ledger or reduced Chat history.

The pinned bridge's prefix comparison is a heuristic workaround, not a protocol guarantee. Implementations must not generalize it as a formally correct way to classify mixed snapshots and chunks: valid independent text can equal, extend, or shorten prior text. Gateway protocol v4 already supplies `deltaText` and `replace`; a durable fix must consume those explicit operations under the matching `runId`, define replacement behavior for the ACP client, and retain content-based comparison only as a bounded legacy fallback. Embedded stream processing must distinguish the latest parser-observed assistant text from the latest text successfully emitted to Gateway. Message-end finalization reconciles the durable final snapshot against emitted state, so an observed but undelivered tail cannot suppress its own retry. Gateway must retain the run's assistant buffer while a lifecycle error is provisional during retry grace. Terminal Chat projection flushes that buffer before cleanup; if a subsequent lifecycle start proves that a retry began, Gateway clears the prior attempt at that start boundary instead. When an aborted Chat terminal carries the buffered assistant message, the bridge must record any unseen text through the same bounded delta path before settling the prompt as cancelled. A true error terminal may still flush real buffered assistant text as an ordinary delta, but its synthetic error message remains error state rather than assistant output.

Repeated Gateway restart recovery must link each recovery run to its directly interrupted predecessor so ACP can adopt the chain one run at a time. Gateway must retain the latest persisted lifecycle owner across terminal settlement and overwrite it on the next run start. Startup orphan detection that establishes the current lifecycle owner must retire guarded-run markers inherited from the prior process before selecting the next predecessor. After a reconnect loses process-local terminal caches, `agent.wait` may use terminal session state only when the caller supplies the owning session key and the persisted lifecycle owner exactly matches the requested run id; it must not infer completion from transcript content or an unscoped session status.

ACP is the preferred authority for every Chat semantic it exposes, including session routing, workspace and execution `cwd`, prompt/timeline state, `usage_update` metadata, and standard resource or attachment semantics. If ACP provides the value or event, implementations must not replace it with Gateway snapshots, transcript inference, local configuration, or a parallel projection. Composer context usage is derived only from the active in-memory ACP timeline metadata and validates finite positive `used` and `size` values. Because the pinned ACP SDK does not accept the draft Session Compaction RFD update, compaction is the versioned compatibility exception: patched OpenClaw emits `_meta["openclaw.ai/compaction"]` version `1` on standard `session_info_update` notifications, and Renderer accepts only its documented IDs, statuses, sources, and typed optional fields. Compaction source remains the trigger category; failed terminals may additionally carry a stable string `reasonCode` and a producer-trimmed reason capped at 500 characters. Renderer displays that reason only on failed rows and never treats arbitrary metadata or a compaction summary as visible failure detail. Actual `/compact` and AgentSession compactions use the structured agent lifecycle; explicit context-engine overflow, preflight, and timeout recovery calls publish direct structured start and terminal events regardless of `ownsCompaction`, while direct `sessions.compact` uses the `session.operation` lifecycle. Stderr, usage changes, and assistant prose are never compaction evidence. Remove this metadata producer and validator and consume the native update when the pinned SDK accepts it and the distributed OpenClaw adapter emits it for the same live and replay paths. Any other bypass is permitted only when upstream ACP has no equivalent; it must be narrow, bounded, session- and generation-scoped, and documented with its rationale, source, limits, reconciliation behavior, and removal condition in a relevant Harness reference or rule.

A complete ACP event ledger is the authoritative `session/load` replay source and must not be replaced by transcript comparison. Patched OpenClaw replays its complete ledger unchanged and in order, then may append only bounded transcript records with finite timestamps strictly newer than the greatest finite ledger event timestamp. When no ledger event has a finite timestamp, the bounded transcript fallback remains available. Records at or before that high-water mark, records without finite timestamps, and transcript-fetch failures never alter or remove ledger events. When the ledger is unavailable or incomplete, patched OpenClaw may project each durable compaction record present in its bounded `sessions.get` response as a completed version `1` compaction marker in response order, without the summary. Records outside that bounded response are not loaded or implied. ClawX Main and Renderer consume ordinary ACP replay notifications and never read ordinary transcript prose to repair text or compactions.

An existing but incomplete ACP event ledger uses the same bounded transcript tool reconstruction path as an unavailable ledger.

ACP replay is the primary history authority. OpenClaw's native ACP adapter may reconstruct persisted transcript `toolCall` and `toolResult` records as standard `tool_call` and `tool_call_update` events when its structured event ledger is unavailable; ClawX consumes those events normally and does not perform that reconstruction itself. The only approved ClawX transcript-derived content supplements are best-effort recovery of asynchronous image-generation completions with proven `image_generate` context and recovery of explicit line-leading assistant OpenClaw `MEDIA:` attachment directives omitted by ACP. The general attachment exception does not require image-generation context, but it recovers only attachment references. When ACP replay for a cron session is completely empty, scheduled-task prompt and completion summaries may instead come from Main's typed cron-history host API. This cron exception must be anchored by Gateway `cron.runs` (with a Main-owned legacy file fallback), be generation-scoped and in memory, and never replace or duplicate non-empty ACP replay. When an anchored run summary carries OpenClaw's bounded-summary ellipsis, Main may recover that run's final assistant text from the identified run transcript only when it is longer and shares the complete persisted summary prefix; missing, mismatched, or unbounded summaries remain unchanged. A separate metadata-only supplement may annotate an ACP-replayed assistant turn with whole-turn duration because ACP `session/load` omits the original event timestamps; it cannot create turns or content. Transcript user records with trusted `inter_session` or `internal_system` provenance are control records rather than visible turn boundaries, so later assistant and tool-result timestamps continue the preceding real user turn, including across Gateway restart recovery. These exceptions remain marked and in memory; do not generalize them to bare paths, surrounding transcript prose, arbitrary ordinary messages, tool cards, plans, permissions, thoughts, file activity, or any parallel persisted history.

After a successful ACP prompt settles, Renderer must perform one same-session ACP `session/load` hydration while retaining the live timeline. Renderer may replace visible timeline content only in one atomic commit when replay is non-empty, not resumed, and still current for the session, generation, load request, and connection identity. Failed, empty, resumed, or stale replay must preserve the settled live content; a successful empty or resumed load must still adopt Main's committed routing generation without replacing visible items.

The pinned ACP adapter may keep one passive `sessions.messages` subscription for the loaded session independently of prompt-lifetime references. It releases or replaces that subscription on close, shutdown, or loaded-session replacement. Only a no-pending `announce:v1` Chat run for the exact loaded session may use this path; it emits ordinary recorded ACP assistant deltas and a recorded terminal snapshot checkpoint. Normal settled runs and unrelated sessions are ignored. A terminal may flush actual assistant text, but synthetic error detail is error state and must not be emitted as assistant text.

Historical transcript reads are limited to the newest `1000` message records. A successful live prompt reads content immediately and retries exactly once after `1500 ms`. General attachment and timing alignment treat history as a suffix and match the binary-free OpenClaw prompt-text projection of structured ACP user blocks by duplicate occurrence from the tail; they must not parse or globally remove user-authored resource marker text. Attachment-only empty projections remain eligible, and live content alignment also requires the current optimistic user identity. Every asynchronous result must retain the same active session, generation, supplement operation and attempt, and live turn where applicable. Unmatched, ambiguous, superseded, or stale work cannot mutate the timeline or timing annotations.

The composer plan indicator may identify an `update_plan` tool call from its tool title, but it derives plan entries only from validated structured `ToolCallItem.input`. It must select the newest non-failed valid input in the active ACP timeline, fall back only to an earlier valid structured input when a newer update fails, and remain scoped to that session's replay. It must not reconstruct plan data from a tool title, tool output, assistant prose, or a persistent or global cache. When ACP replay omits valid structured plan input, including after a session switch, reload, timeline replacement, or restart, the indicator must be hidden rather than retaining or inventing a plan.

Tool-card presentation may derive its localized label and icon from the tool title. Every `write` call uses the Write presentation, and every `sessions_spawn` call uses the Spawn subagent presentation without inspecting or requiring a `runtime` argument.
