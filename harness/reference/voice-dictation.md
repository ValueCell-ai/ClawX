# Voice Dictation (Speech-to-Text Input)

## Microphone permission recovery

After the configured-profile guard, composer activation reads `hostApi.asr.getMicrophoneAccess()`. Main uses prompt-free `systemPreferences.getMediaAccessStatus('microphone')` on macOS/Windows; other platforms return unknown. Denied/restricted status opens localized guidance without capture. Unknown, not-determined, and failed reads allow the normal `getUserMedia` path. A `MIC_UNAVAILABLE` capture failure triggers another permission read to catch a first-use refusal; only denied/restricted replaces the generic error. Generation cancellation covers both reads, including disabling and unmount.

The dialog's explicit `hostApi.asr.openMicrophoneSettings()` action opens only Main-owned fixed URLs: `x-apple.systempreferences:com.apple.preference.security?Privacy_Microphone` or `ms-settings:privacy-microphone`. Unsupported platforms do nothing. Launch failure is visible; closing/settings launch never starts recording. A new mic click reads fresh status. Restricted access may require an administrator/device-policy change. The dialog is a compact, centered, padded card with a title, a short permission explanation, and close/settings actions. Detailed platform, restart, and development-launcher instructions remain in documentation rather than in the dialog.

Permission status does not verify signing or hardware. Hardened Runtime microphone capture requires `com.apple.security.device.audio-input` for the app/inherited helpers plus the usage description. Mocked unit/E2E coverage neither changes TCC nor verifies a signed installed build. The installed 0.5.7 entitlement issue requires a rebuilt, correctly signed installation; guidance alone cannot repair that binary.

### Local macOS builds: split permission identities

A locally packaged app that skips application signing can retain Electron's linker-generated signature (`Identifier=Electron`, `flags=adhoc,linker-signed`, `Info.plist=not bound`). This is different from explicitly ad-hoc signing the completed application bundle. In the observed local 0.5.7 build, macOS TCC attributed Main's permission reads/requests to `app.clawx.desktop` (bundle identity), but Core Audio requests from the Helper to `/Applications/ClawX.app/Contents/MacOS/ClawX` (executable-path identity). System Settings showed two ClawX microphone entries, one with the app icon and one with a terminal icon.

This produced a confirmed false-positive permission state: Main returned `granted` while the path entry was denied; `getUserMedia` succeeded with a live, enabled, unmuted track and a running AudioContext, but all 475,136 samples in a 10-second probe were zero. Enabling only the path entry, without changing capture code or restarting, yielded 473,915 nonzero samples in the same-size probe. Only counts and peak amplitude were inspected; no recording was saved or transcribed. An explicit Main `askForMediaAccess` request opened a real consent dialog for the bundle identity but did not resolve the separately denied path identity. Do not treat a successful request or healthy-looking track metadata as proof that this packaging issue is repaired, and do not classify ordinary silence as permission denial.

For certificate-free local packaging with this repository's electron-builder **26.16.0**, explicitly sign the completed bundle rather than skipping signing:

```sh
pnpm run package:mac:local --arm64 --config.mac.identity=- --config.mac.notarize=false
```

Use `--x64` for an Intel build. Keep the existing audio-input and disable-library-validation entitlements. Release builds should retain Developer ID signing and notarization. Inspect the resulting app/helper signatures with `codesign -dvv --entitlements - <bundle>`; the main app should identify as `app.clawx.desktop` with a bound Info.plist, rather than retaining the raw Electron linker signature. Rebuilt signed-package acceptance still requires checking that permission denial blocks capture and that granting permission allows real microphone input. Existing duplicate TCC entries are not automatically removed by a rebuild; never reset TCC or alter grants automatically.

## Recording and transcription

When Developer Mode is enabled, ClawX adds a microphone button to the chat composer that turns spoken audio into prompt text. Press once to record, press again (or wait for the 180 s cap) to stop, and the transcription is inserted at the textarea cursor. Escape cancels and discards a recording, and the composer textarea is locked from the moment recording starts until transcription finishes so the insertion point cannot drift. With Developer Mode disabled, neither the composer microphone nor the Models page Speech-to-text tab is rendered, and a direct `?tab=voice` URL falls back to Chat models.

The feature deliberately uses batch transcription instead of streaming. Streaming ASR has no universal wire protocol — every vendor (iFlytek, Deepgram, AssemblyAI, Tencent) defines its own WebSocket dialect — while OpenAI's `POST {baseUrl}/audio/transcriptions` is the de-facto standard adopted by OpenAI, Groq, SiliconFlow, DeepInfra, Fireworks, and local servers such as whisper.cpp and LocalAI. ClawX therefore records locally, uploads one WAV file when the user stops, and inserts the returned text. Two wire protocols are supported, selected by the `protocol` field of `AsrConfig` (legacy stored configs without the field mean `transcriptions`; see `normalizeAsrProtocol`):

- **`transcriptions`** — multipart `POST {baseUrl}/audio/transcriptions` with `file` (`recording.wav`, 16 kHz mono PCM16), `model`, and an optional `language` (ISO-639-1, for example `zh` or `en`; the field is omitted entirely when unset so the server auto-detects). Returns `{ text }`.
- **`chat`** — JSON `POST {baseUrl}/chat/completions` with `{ model, stream: false, messages: [{ role: 'user', content: [{ type: 'input_audio', input_audio: ... }] }] }`. The `input_audio` encoding is preset-dependent: the `bailian` preset uses Alibaba Cloud Model Studio's dialect (Data URI `data:audio/wav;base64,<base64 wav>` with no separate `format` field), while every other preset (custom endpoints) follows OpenAI's schema (bare Base64 in `data` plus `format: 'wav'`). No vendor `asr_options` is sent. The transcript is read from `choices[0].message.content` (a string, or text parts joined when the content is an array).

Both protocols share a 30 s timeout, Bearer authorization, the same HTTP-status→error-code mapping, and treat an empty result as a business error rather than success.

Audio capture lives entirely in the renderer. `getUserMedia` opens a mono stream with echo cancellation, noise suppression, and auto gain; a `ScriptProcessorNode` (4096 samples) feeds a pipeline that linearly resamples to 16 kHz, encodes little-endian PCM16, and prepends a 44-byte RIFF header on stop. Fewer than 300 ms of valid audio rejects the take. While recording, the same PCM chunks are reduced to an RMS level (clamped to 0–1 with a 4× gain) and pushed into a 24-sample ring buffer in the `useVoiceDictation` hook; the composer button polls that buffer at 120 ms to draw a five-bar waveform whose heights track real loudness, so silence sits at the floor and speech rises with volume. Recording state is a three-state machine (`idle` / `recording` / `transcribing`) guarded by a synchronous re-entry lock and a generation counter that invalidates stale async continuations on unmount, draft switches, and cancels — the same race family that previously produced double-session bugs, including a memoized recorder `stop()` so concurrent stop calls share one terminal outcome.

All privileged work happens in the Main process through the existing host-invoke registry as a dedicated `asr` module (`getConfig` / `saveConfig` / `transcribe`). The renderer never fetches external endpoints and never sees the API key: `getConfig` returns only a `hasApiKey` boolean. Because Electron flattens thrown host errors to a message string, ASR error codes are serialized into the message as `ASR:<CODE>:<message>` and parsed back by `parseAsrErrorCode` in `shared/asr/errors.ts`; recognized codes (`AUTH`, `RATE_LIMITED`, `SERVER`, `NETWORK`, `EMPTY_RESULT`, `INVALID_INPUT`, `NOT_CONFIGURED`, `REQUEST`) map to per-code i18n copy in both the composer toasts and the settings form, with `REQUEST` as the fallback.

Configuration is a single endpoint profile, not a multi-account structure. `AsrConfig` holds a `protocol` (`transcriptions` | `chat`), a `preset`, `baseUrl`, `model`, and optional `language` (transcriptions protocol only). The provider preset list is protocol-scoped (`ASR_PRESETS_BY_PROTOCOL` in `shared/asr/presets.ts`): transcriptions offers `openai` / `groq` / `siliconflow` / `custom` (base-URL defaults `whisper-1`, `whisper-large-v3`, and `Qwen/Qwen3-ASR-1.7B`; custom leaves both empty), while chat offers `bailian` / `custom` (`bailian` prefills `https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` with model `qwen3-asr-flash`; the user replaces the `<WorkspaceId>` placeholder). Picking a preset or protocol overwrites the base URL and model with defaults. The config lives in a dedicated electron-store file (`clawx-asr`) while the API key reuses the provider secret store under the fixed account id `asr` — an empty string clears it, `undefined` leaves it untouched. Nothing is pushed to the OpenClaw gateway. The settings surface is the Models page. Both Speech-to-text and image generation are experimental surfaces gated behind Developer Mode; Chat models remains available unconditionally. Clicking the mic with an incomplete profile toasts guidance and routes to `/models?tab=voice`, and the Base URL field renders a non-editable `/audio/transcriptions` suffix only for the transcriptions protocol's standard presets (openai/groq/siliconflow); when the preset is `custom` or the protocol is `chat`, the suffix is hidden. Under the transcriptions protocol a `custom` preset sends the entered URL as the full request endpoint (no path appended, because custom providers may expose non-standard paths); under the chat protocol the entered URL is always a base URL and `/chat/completions` is appended. Selecting `bailian` renders two localized hints — its Data URI `input_audio` requirement (with an inline docs link opening Aliyun's OpenAI-compatible ASR guide) and the `<WorkspaceId>` placeholder/region note — plus a provider-console link for the API key (siliconflow and bailian only).

macOS packaging declares `NSMicrophoneUsageDescription` and enables `com.apple.security.device.audio-input` in the app and inherited helper entitlements for Hardened Runtime audio capture. The usage description explains the TCC prompt; it does not replace the signing entitlement. Chromium's user-triggered `getUserMedia` path requests consent, so the Main process needs no explicit `askForMediaAccess` call, and the default window session needs no permission handler — the deny-all handler in `web-browser-session.ts` only governs the embedded-browser guest session.

Testing mirrors the layering. Pure WAV math (resampling, PCM16 encoding, header bytes) and the recorder (against a fake `AudioContext` graph, including the double-stop race) are unit-tested; the hook uses fake timers for the 180 s cap and 250 ms tick; the Main client stubs `fetch` for status-code mapping and multipart shape; the settings form and Models tab have component tests; and `tests/e2e/voice-dictation.spec.ts` covers both the insert-at-cursor happy path and the unconfigured guidance path by mocking `asr` host actions through `installIpcMocks` and stubbing `getUserMedia` with an oscillator-backed stream. The specs are ordinary parallel tests — the microphone is always mocked, so no OS-global state is touched and no `@exclusive` tag applies. Developer-mode coverage also verifies that both the composer microphone and Speech-to-text tab are hidden while the mode is off and become visible after it is enabled.
