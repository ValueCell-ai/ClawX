# Voice Dictation (Speech-to-Text Input)

ClawX adds a microphone button to the chat composer that turns spoken audio into prompt text. Press once to record, press again (or wait for the 180 s cap) to stop, and the transcription is inserted at the textarea cursor. Escape cancels and discards a recording, and the composer textarea is locked from the moment recording starts until transcription finishes so the insertion point cannot drift.

The feature deliberately uses batch transcription instead of streaming. Streaming ASR has no universal wire protocol — every vendor (iFlytek, Deepgram, AssemblyAI, Tencent) defines its own WebSocket dialect — while OpenAI's `POST {baseUrl}/audio/transcriptions` is the de-facto standard adopted by OpenAI, Groq, SiliconFlow, DeepInfra, Fireworks, and local servers such as whisper.cpp and LocalAI. ClawX therefore records locally, uploads one WAV file when the user stops, and inserts the returned `{ text }` payload. The request is multipart form data with `file` (`recording.wav`, 16 kHz mono PCM16), `model`, and an optional `language` (ISO-639-1, for example `zh` or `en`; the field is omitted entirely when unset so the server auto-detects). Authorization is a Bearer token, the request times out after 30 s, and an empty `text` is treated as a business error rather than success.

Audio capture lives entirely in the renderer. `getUserMedia` opens a mono stream with echo cancellation, noise suppression, and auto gain; a `ScriptProcessorNode` (4096 samples) feeds a pipeline that linearly resamples to 16 kHz, encodes little-endian PCM16, and prepends a 44-byte RIFF header on stop. Fewer than 300 ms of valid audio rejects the take. While recording, the same PCM chunks are reduced to an RMS level (clamped to 0–1 with a 4× gain) and pushed into a 24-sample ring buffer in the `useVoiceDictation` hook; the composer button polls that buffer at 120 ms to draw a five-bar waveform whose heights track real loudness, so silence sits at the floor and speech rises with volume. Recording state is a three-state machine (`idle` / `recording` / `transcribing`) guarded by a synchronous re-entry lock and a generation counter that invalidates stale async continuations on unmount, draft switches, and cancels — the same race family that previously produced double-session bugs, including a memoized recorder `stop()` so concurrent stop calls share one terminal outcome.

All privileged work happens in the Main process through the existing host-invoke registry as a dedicated `asr` module (`getConfig` / `saveConfig` / `transcribe`). The renderer never fetches external endpoints and never sees the API key: `getConfig` returns only a `hasApiKey` boolean. Because Electron flattens thrown host errors to a message string, ASR error codes are serialized into the message as `ASR:<CODE>:<message>` and parsed back by `parseAsrErrorCode` in `shared/asr/errors.ts`; recognized codes (`AUTH`, `RATE_LIMITED`, `SERVER`, `NETWORK`, `EMPTY_RESULT`, `INVALID_INPUT`, `NOT_CONFIGURED`, `REQUEST`) map to per-code i18n copy in both the composer toasts and the settings form, with `REQUEST` as the fallback.

Configuration is a single endpoint profile, not a multi-account structure. `AsrConfig` holds a `preset` (`openai` | `groq` | `siliconflow` | `custom`), `baseUrl`, `model`, and optional `language`; picking a preset overwrites the base URL and model with defaults (`whisper-1`, `whisper-large-v3`, and `Qwen/Qwen3-ASR-1.7B` respectively; custom leaves both empty). The config lives in a dedicated electron-store file (`clawx-asr`) while the API key reuses the provider secret store under the fixed account id `asr` — an empty string clears it, `undefined` leaves it untouched. Nothing is pushed to the OpenClaw gateway. The settings surface is the Models page, whose management tabs (Chat models, Speech-to-text) render unconditionally because dictation is a mainstream composer feature; only the image-generation tab remains gated behind developer mode. Clicking the mic with an incomplete profile toasts guidance and routes to `/models?tab=voice`, and the Base URL field renders a non-editable `/audio/transcriptions` suffix so users can see exactly which path segment is appended.

Packaging restores `NSMicrophoneUsageDescription` (previously removed with the Realtime Talk feature); Chromium surfaces the macOS TCC prompt from the plist entry alone, so the Main process needs no explicit `askForMediaAccess` call, and the default window session needs no permission handler — the deny-all handler in `web-browser-session.ts` only governs the embedded-browser guest session.

Testing mirrors the layering. Pure WAV math (resampling, PCM16 encoding, header bytes) and the recorder (against a fake `AudioContext` graph, including the double-stop race) are unit-tested; the hook uses fake timers for the 180 s cap and 250 ms tick; the Main client stubs `fetch` for status-code mapping and multipart shape; the settings form and Models tab have component tests; and `tests/e2e/voice-dictation.spec.ts` covers both the insert-at-cursor happy path and the unconfigured guidance path by mocking `asr` host actions through `installIpcMocks` and stubbing `getUserMedia` with an oscillator-backed stream. The specs are ordinary parallel tests — the microphone is always mocked, so no OS-global state is touched and no `@exclusive` tag applies.
